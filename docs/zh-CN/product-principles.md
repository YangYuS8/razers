# 产品原则

RazeRS 服务于硬件拥有者，让设备配置简单、快速、清晰、可靠；不用于销售其他产品或
把用户锁进生态系统。

## 对用户的承诺

- 没有广告、赞助位、推广通知或付费升级诱导。
- 本地控制、配置、更新、诊断和社区支持数据不要求账号。
- 默认没有遥测、分析、崩溃上传或设备数据上传。未来网络动作必须解释传输内容并先取得同意。
- 不为提高使用时长而故意拖慢、隐藏或拆碎核心功能。
- 如实展示当前可用内容，不把证据支持的可能性伪装成控制功能，清楚标记实验性行为。

## 交互标准

常用流程应当直观：打开 RazeRS、选择设备、调整设置、确认是否生效。
高频设置靠近概览；高级或危险操作可逐步展开，但必须能找到并有文档。

每个控制需要当前值、范围或可选项、持久化范围、应用状态和有效的错误说明。
可撤销设置应即时预览并支持撤销；持久写入需要明确摘要与确认。
不支持的能力应解释原因，不应悄悄消失。

界面跟随系统主题与缩放，支持键盘导航和平台无障碍 API，不依赖动画或颜色传达关键状态。
空列表、加载中、权限不足、断开连接、部分支持和错误均是一等状态。

## 功能完整性

桌面端应使用共享能力描述符，不能为每个产品维护一套手写页面。
一项能力只有在 UI、校验、驱动、回放测试、状态/错误、持久化行为和文档一致时才算完成。
通过可复用清单和驱动扩展覆盖面；型号例外写进带来源的已审阅 quirks，不能隐藏在 UI 条件中。
这让单人维护者可以复用社区实测，而不必购买所有设备。

## 当前边界

私有 Agent 子进程只发现 HID 描述符，按 USB 产品标识归并接口，通过继承管道返回摘要。
桌面展示已整理或导入的知识，并说明控制尚未开放的原因。两者都不会打开设备、读取序列号值、
发送报告或后台联网。仅用户主动点击文档链接时才打开外部浏览器。
